# Architecture decisions (append-only)

## D1 — Extend ClickHouse Observe instead of a new plugin (2026-11-17)
v0.10.0 already implements most of Discover on ClickHouse (KQL → SQL with autocomplete, filter pills, field sidebar + stats popover, histogram + breakdown, grid with cell actions, detail drawer, diagnostics). Build Lens and the gaps on top. Spec: `docs/spec/80-blueprint.md`.

## D2 — Frontend-only, queries through grafana-clickhouse-datasource
Keep using `src/data/runQuery.ts` (`getDataSourceSrv().get(uid).query()` with `{rawSql, editorType:'sql', format:1}`). The repo removed its Go backend in 0.4.7. Add a backend only if pattern clustering needs it.

## D3 — Plain React + @grafana/ui, no Scenes migration
Migration cost outweighs the benefit; the app already has its own state + URL sync.

## D4 — Lens rendering
- Bar / line / area (the default auto charts): custom-drawn, generalising `VolumeHistogram.tsx`, because Grafana panels give no one-click "point clicked" callback and the spec requires one-click filter + the multi-dimension "Select filters to apply" chooser.
- Table, Metric/Stat, Pie, Heatmap: `PanelRenderer` (`@grafana/runtime`, public but `@internal`) inside `PanelContextProvider` (`@grafana/ui`, alpha) for table cell filters (`onAddAdHocFilter`) and brush (`onChangeTimeRange`). Isolated in `src/lens/render/` so a Grafana API change touches one place.

## D5 — Deterministic fixture for tests
`default.spec_logs` (`scripts/clickhouse-init/04_spec_fixture.sql`): fixed window 2026-01-01..2026-01-08 UTC, no TTL, 41,520 rows incl. a payments incident on 2026-01-05 09:00–11:00. Tests assert exact counts from `tests/fixture.ts`, never the Kibana numbers in the spec.

## D7 — URL is the shared search context; pinned filters also in session storage (SHARED-STATE)
Every page reads/writes the same URL params (`q, filters, cols, sort, from, to, ds, interval, bd`), like Kibana's `_g`/`_a`, so hand-offs between pages are just links built by `buildAppPageUrl` (`src/state/sharedSearch.ts`). Pinned pills (`FilterPill.pinned`) are also kept in per-tab session storage (`clickhouse-observe.pinnedFilters`), each with the table it was pinned on. The store changes only on explicit transitions (pin, unpin, edit/exclude of a pinned pill, delete of a pinned pill); disable and Clear all are page-only. Pin flags are shown only for conditions in the user's own store (foreign links/saved searches can't plant pins). Pins merge into pages opened without `filters`, loaded saved searches and data view switches — disabled on a view reading a different table. A field breakdown is stored by `FieldModel.id` and resolved once discovery finishes. No React context store was added: LogsExplorer already owns its state and the Lens page will decode the same URL.

## D8 — One autocomplete service for every input (SHARED-AUTOCOMPLETE-01)
`src/autocomplete/service.ts`: `useAutocompleteSources({config, query, timeRange, fieldIndex})` gives `loadValues`/`loadMapKeys` scoped to the time range, search and filters; lookups never reject or throw (failures resolve empty; an unparsable search is dropped from the scope), the scope is compiled once per change, and the cache key distinguishes before/after field discovery. `rankFields(fields, prefix, {allow})` (`src/autocomplete/rankFields.ts`, pure) is the one field ranker: name or display name, prefix-first; the KQL suggestion engine uses it too. New inputs (filter builder, Visualize field pickers, formula editor) must use it — checklist in `docs/spec/30-shared.md`.

## D9 — Dirty state only for the query (DISC-SEARCH-02 / DISC-TIME-02)
Grafana's time picker applies a range immediately (no pending state), so only the KQL bar has a dirty state: when the typed query differs from the committed one, its search icon becomes a primary "Update" button. Matched-term highlighting (`src/sql/kql/highlight.ts`) mirrors the SQL that matched (toSql): fields resolve via `resolveField`, field wildcards expand against discovered fields, an unresolvable `field:value` is a body match on its raw text, wildcard values are one ordered pattern, phrases match on word boundaries; negated/exists/range terms and raw-SQL mode get no highlights. One compiled matcher per column.

## D10 — Action registry (SHARED-ACTION-01)
`src/actions/registry.ts` defines each value/field action once (icon, short tooltip, specific accessible name, compatibility, behaviour): `valueActions(ctx, host, ids?)` → filter for / filter out / copy; `fieldActions` → exists / does not exist. A surface passes an `ActionHost` (`addFilter` omitted = read-only → copy only) and keeps its own layout. Grafana's `IconButton` uses `tooltip` as its accessible name, so icon surfaces use `ActionIconButton` (Tooltip wrapper) to keep names like "Filter for Service: payments". The field list's "filter out rows that have this field" is now a `not_exists` pill (same SQL as the old `= ''`).

## D46 — Kibana parity: Save and return, Discover dashboard export, Share in Visualize, short links (PARITY-DASHBOARDS)
PARITY-DASHBOARDS (Kibana 9.5.6 comparison, user request 2026-11-19). **Save and return:** the panel-menu link adds the dashboard uid, panel id and the dashboard's time (`dash`, `panel`, `dfrom`, `dto`) to the Visualize URL, validated in `readDashboardReturn` / `editInVisualizePath`; nothing else about the session changes (they are not part of the remembered search context or the share link). Visualize loads the dashboard once on entry (`loadReturnTarget`): its panel title / description prefill the dialog and its `version` is the optimistic lock — the save replaces the panel by id in the JSON loaded at entry (`replacePanelInDashboard`, rows included) and posts it with `overwrite: false`, so Grafana answers `412 version-mismatch` if the dashboard changed since; we explain it rather than merging. The dialog is kept (Kibana saves directly) so the title can still be changed; `Save as new` is the old flow. A library-panel reference replaced this way becomes an inline panel (updating the library element would change every dashboard using it). **Discover → dashboard:** a new dashboard gets Discover's range (relative strings kept); existing dashboards keep theirs. The logs panel stays a Grafana `table`: the `logs` panel shows one text line per document and hides the other fields behind a details toggle, so Discover's chosen columns can't be shown side by side; the table gets Discover's columns through one `organize` step over the grid projection, fixed widths for Time / Level / Service / Trace, wrapped Message and a footer row count (of the rows shown — the panel keeps Discover's 200-row limit, so it is not the total hit count). "Open in Discover" uses the same panel-menu extension pattern as Edit in Visualize (`observeDiscover` on the target, the Discover URL parameters minus time, filtered and capped; Discover sanitizes them as a shared link). **Legends:** Grafana's `partitionByValues` labels each series field with the split value and names it `<field> <value>`; a rename before partitioning didn't survive in the comparison Grafana, so split time series keep the metric aliases and set `displayName` by override (`byName m<i>` → `${__field.labels.b1}`, or `… · <metric>` with several metrics); per-metric appearance overrides match the alias in that case. The volume panel does the same with `${__field.labels.level}`. **Empty buckets:** Grafana fills nothing for a table-format query and `insertNulls` needs a fixed interval, so count-only charts gap-fill in SQL with `WITH FILL`, the breakdown columns leading so ClickHouse fills per breakdown value (`use_with_fill_by_sorting_prefix`, default on since 23.x); other metrics keep gaps. **Short links:** Grafana's `/api/short-urls` with the path relative to the root; the dialog shows the full link until the short one arrives and falls back to it on any error. **Saved searches button:** secondary + folder icon + caret, no tooltip.

Deferred: - Kibana's direct (no-dialog) Save and return, and updating a library panel's element on Save and return.
- A total hit count on the exported logs panel (needs a second query / a stat panel); the footer counts the rows shown.
- Legend names for category charts with a breakdown and several metrics (`joinByField` path) — unchanged.
- Gap filling for non-count metrics in saved panels (Grafana `insertNulls` only with a fixed interval).
- Storing the time range when adding to an existing dashboard (Kibana's "Store time with dashboard" option).
- Short-link expiry / cleanup (Grafana's own policy applies).

## D45 — Kibana parity: document paging, column resize and menu, sidebar, sort tie-break, context view, single-document link (PARITY-GRID)
PARITY-GRID (Kibana 9.5 comparison, grid / document panel / context view / field popover). Document navigation walks the loaded rows (`rows`, 200 initially) rather than the grid page, like Kibana's flyout over its sample; stepping past the last loaded row calls the grid's own `ensureRows` and the grid page follows the open document (`src/pages/_docNav.ts`). Keyboard: ←/→ (Kibana's flyout keys), ignored in text inputs and for events from portalled popovers; Escape closes; the panel focuses itself on mount, and the grid returns focus to the row's button when the selection clears and focus would otherwise land on `<body>`. Column widths are part of `SelectedColumn` (`width?`), so they travel with `cols` and saved searches like order does; the queries use `stripColumnWidths` behind a string-keyed memo, so a resize never re-runs anything. Widths are applied as width/min/max on the header and cells plus a capped content box (table cells treat width as a hint). The header name opens a menu (not a sort): sort direction is explicit (`SET_SORT` gained `dir`), which made the header-click toggle unnecessary. Non-time sorts add `, <time> DESC`. `ADD_COLUMN` refuses a column whose expression is already shown, except the core time column (a converted time field shows a converted value). The sidebar min width (200 px) and `min-width: 0 !important` on the results / table panes override `useSplitter`'s inline `min-width: min-content`, which was what let a wide grid push the sidebar to its 60 px floor. "View single document" reuses the surrounding-documents anchor (epoch-ns timestamp + `cityHash64` row id) instead of inventing a second identity; the page navigates in the same tab (an async anchor lookup before `window.open` would be popup-blocked). The JSON tab converts only the mapped time column and `__timestamp` (epoch ms → ISO; ClickHouse DateTime text keeps its fractional digits). Map keys: one click from the opened key list (a per-key ⊕), not from the sidebar row itself — keys are only known after the on-demand query, and another agent may flatten Map keys into the field list. Popover caption: "sample records" only when the sample reached its cap (5,000 stats / 500 keys).

Deferred: - Item 10 (chart caption overlap in the detail panel) — handled by another agent.
- Map keys as one click directly from the sidebar row: needs the keys in the field list (another agent may flatten Map keys); here it is one click from the opened key list.
- Header menu: Copy column (all values) and Edit data view field; header line limits.
- The document panel's width is the existing splitter (persisted per viewer), not a separate drag handle on the panel edge.
- "View single document" opens in the same tab (Kibana: new tab).

## D44 — Kibana parity: histogram brush, inclusive counts, intervals and axis, refresh off, no default breakdown (PARITY-HISTOGRAM)
Kibana parity for the Discover histogram and time (comparison against Kibana 9.5.6 on the same fixture, 2026-11-19). (1) **Brush:** `brushRange` (`src/components/_histogramInterval.ts`) maps the dragged pixels to time inside each bar slot (bar `i` plus a fraction of its width; linear for fixed-width buckets), clamps to the drawn extent, rounds outwards to whole seconds and enforces a minimum width of max(1 s, one pixel of time). Whole seconds because the ClickHouse datasource's `$__fromTime` / `$__toTime` are second precision (`toDateTime(intDiv(ms, 1000))`): a millisecond `to` would silently drop up to 999 ms of rows while the caption claimed them. Switching every query to the `_ms` macros was not done here (wide SQL churn: Discover, Lens, alerts, panel exports). The Visualize XY brush (`src/lens/render/XyChart.tsx`) has its own linear pixel→time mapping (no snapping) and shares no code with this one; it still emits millisecond times. (2) **Inclusive end:** SQL was already `<= to`; `fillEmptyBuckets` now keeps any bucket the query returned, including one starting at `to`, and still adds no empty filler there. Counts that change: a range whose end instant holds a row gains it (e.g. a one-day window on the fixture, midnight to midnight, is 5,761 rows, not 5,760; whole-fixture counts are unchanged because the last fixture row is 23:59:45). (3) **Intervals:** auto steps gained 15 min, 3 h, 12 h; `resolveInterval` scales a fixed second/minute/hour/day interval above `MAX_BUCKETS` (1,000) to the smallest auto step that is a multiple of the unit and fits, returned as `SECOND × n` with `scaledTo`; week/month/year are calendar widths and never scaled. The Visualize hand-off still carries the chosen unit (Lens applies its own interval rules). (4) **Ticks:** `timeTicks` (`src/components/_histogramTicks.ts`) picks the finest round step whose labels fit (≥ 80 px apart and label width + 16 px), aligned in the browser's zone (days step by calendar days so DST can't move midnight ticks); second lines at most one per ~100 px. Calendar-unit buckets keep index-based date labels. (5) **Partial buckets:** `isPartialBucket(start, width, range)` = starts before `from` or ends after `to` (a bucket ending exactly at `to` is whole). (6) **Defaults:** breakdown default is `none` (derived; `bd` wins); auto-refresh default paused, URL `refresh` validated, encoded only when on. (7) **`bd` normalisation:** `resolveBreakdownField` accepts the exact id or `col:<id>`; once discovery has settled for the URL's own view (`fieldsFor === discoveryKey(config)`, not loading, fields present) an unresolved id is cleared, which drops it from the URL; junk never decoded in the first place.

Deferred: - Millisecond-precise time bounds (`$__fromTime_ms` / `$__toTime_ms` everywhere). Brush and click ranges are whole seconds, so nothing is lost today; sub-second ranges typed in the picker are still truncated to the second by the datasource macros.
- Kibana's red "now" line on the histogram.
- Visualize XY brush: not touched (owned by the XY-chart work); it maps pixels to milliseconds without snapping, so it doesn't have the snapping bug, but its times are not rounded to whole seconds.
- A scaled interval is not carried into Visualize as the scaled width (Explore in Visualize passes the chosen unit; Lens decides its own buckets).
- The field popover's "sample records" wording when every row was used (finding in the same comparison; belongs to the field-popover work).

## D43 — Kibana comparison fixes: Edit in Visualize, parked dimensions, default time range (COMPARE-FIXES)
Kibana comparison fixes (user requests, 2026-11-19). (1) **Parked dimensions:** `LensState.parked` = `{ chartType, subType?, buckets, style?, layers? }`, written by `switchChart` for whatever the target can't show (a dropped date histogram always; other buckets only when the target is Metric / Pie) and read back on the next switch (a parked date returns to X, other buckets after the visible ones; Style / layers only on XY). `chartType` is the last chart that could show them, so a time field dropped on Metric goes back there (`addTimeBucket`, used by both the workspace drop and bucket slots). Parked state rides in the `lens` URL param: `cleanParked` keeps known chart types, at most 8 buckets through the same `cleanBuckets` as visible ones, and `cleanStyle` / `cleanLayers`; `sanitizeLens` drops parked buckets and computed lines on fields the view lacks; `queryShape` strips it, so parking never re-runs the query. (2) **Edit in Visualize:** the panel keeps its Visualize state as URL parameters on its query target (`observeVisualize`), not a separate store, so it survives dashboard export / import and needs no backend; a `grafana/dashboard/panel/menu` link extension (declared in plugin.json) shows only when a target has it. Dashboard JSON is untrusted: `editInVisualizePath` passes only `lens`, `q`, `filters`, `ds`, caps the value at 16,000 characters, always builds the path under the plugin's own route, and Visualize decodes / sanitizes it like a shared link. Time comes from the dashboard, as in Kibana. (3) **Default time range:** `jsonData.defaultTimeRange` (admin config), cleaned by `cleanDefaultTimeRange` (strings ≤ 64, both parse with Grafana dateMath, from < to, else the last hour) and provided by App through `DefaultTimeRangeContext`. Kibana's comparison stack opening on the data was its `timepicker:timeDefaults`, not an automatic data-range search, so the equivalent here is the same kind of setting. (4) The Visualize toolbar's `database.table` label is gone; the active table is in the picker's `title`.

Deferred: - Kibana's "Save and return" from Visualize back to the dashboard (replacing the original panel in place); Edit in Visualize opens a fresh Visualize session and saving adds a new panel.
- An automatic "time range with data" when the default range is empty (Kibana doesn't do it either; its Discover offers a "search entire time range" action, not implemented).

## D42 — Keyboard and accessibility (SHARED-A11Y-01)
SHARED-A11Y-01 (#33). Grafana's own components (Modal, Drawer, Dropdown / Menu, Combobox, Toggletip) already trap or manage focus and close on Escape, so they are kept as they are; only Toggletip gets a `role="dialog"` wrapper because it sets no role. The plugin's custom Portal popovers share one hook, `usePopoverDialog` (`src/components/a11y/dialog.tsx`): role dialog, the Kibana hint as `aria-describedby`, Escape inside (respecting an Escape a child already used, e.g. an open Combobox list — downshift calls `preventDefault`) and on the page while focus is still outside, focus into the popover on the next frame unless a child focused something, and focus back to the opener (or a given element, e.g. the pill button) on close only when focus would otherwise be lost (on `<body>`), so a click on another control keeps its focus. The opener is captured during the first render, before any child effect can move focus. The inline dimension editor only reacts to Escape from inside (`escapeFromPage: false`), so Escape in another popover or the Inspector drawer does not also close it. Menus use `role="menu"` / `menuitem` with arrow-key movement (`moveMenuFocus`); the filter pill menu's buttons became menuitems (e2e page object updated). Keyboard drag and drop (`src/lens/keyboardDnd.ts`) follows Kibana: a separate focusable handle per field (the row stays the mouse drag source), targets computed from the current chart on every key (same set as the mouse drop zones, same `onAdd` / `addToGroup` calls), focus stays on the handle while lifted, blur cancels, messages through a polite live region. Discover keeps its button alternatives instead of a keyboard drag mode: Add as column (field → grid), Move left / right (column reordering) and the tab menu's Move left / right (tab reordering). The grid keeps DOM focus on the grid element (D12) and points `aria-activedescendant` at the cursor cell; cells stay `td` (role cell) because e2e selects them that way.

Deferred: - A keyboard drag mode on Discover (field → grid column, column / tab reordering): the button alternatives cover the same actions.
- Moving dimensions between Visualize groups by drag (mouse or keyboard): still deferred from LENS-DIM-01.
- Focus trapping inside the custom popovers (Kibana traps; ours are non-modal, Tab may leave them; menus close on Tab).
- Grid cells as `gridcell` with row / column counts (`aria-rowcount`), and a ⌨ Keyboard shortcuts help popover (DISC-TABLE-01 toolbar).
- A full screen-reader pass (NVDA / VoiceOver) and an automated axe scan in e2e.

## D41 — Visualize reference line and annotation layers (LENS-LAYER-01)
LENS-LAYER-01 (#28). Extra layers are one optional list on the chart, `LensState.layers` (`src/lens/layers.ts`): `referenceLine` layers hold lines (static `value` or `computed: {op, field}`), `annotations` layers hold manual (`time`, optional `end`) or query (`query` KQL) annotations; at most 5 layers × 10 items. Untrusted input (URL, draft) goes through `cleanLayers` in `decodeLens`: known kinds and keys only, finite numbers, times within 1970–2200, an `end` only after its start, `#rrggbb` colours, labels capped at 120 characters (rendered as SVG text, never markup), queries capped at 1,000 characters, computed ops from a fixed list, ids `[A-Za-z0-9_-]{1,64}` (bad or repeated ids are replaced). The editors build every change through `cleanLayers` too, and the KQL / number / date inputs validate before applying. `sanitizeLens` drops computed lines whose field is not a discovered field (same rule as dimensions). Layers are display-only for the chart query (`queryShape` strips them); computed values and annotation events come from two separate queries (`useLayerData`, keyed on their own inputs, op `lensLayers`, so the Inspector's chart requests stay the chart's), and a failure just leaves those lines / markers out. Query annotations ignore the chart's own query and filters (Kibana's default "ignore global filters") and use the standard time conditions. Rendering stays in `XyChart`: lines on their value axis (the left one when no series uses the right), annotation markers only on a time X axis of a vertical chart, positioned within the buckets like the brush. Switching between XY types keeps layers; Metric / Table / Pie drop them. Export (`render/layerConfig.ts`): static left-axis lines → `fieldConfig.defaults.thresholds` with `custom.thresholdsStyle` (`line`, `dashed` when every line is dashed / dotted, `+area` when every line fills above); labels, computed lines, right-axis lines (when the chart has a right axis) and annotations have no panel-level Grafana equivalent and are not exported.

Deferred: - **Extra Visualization layer** (another series set with its own data view / chart sub-type): needs multi-query compilation, a second dimension editor and per-layer series merging in `XyChart`; the menu shows it disabled.
- **Layer settings ⚙ (random sampling)** for the data layer.
- Annotation extras from Kibana: "ignore global filters" toggle (always on), text / tooltip fields from the matched documents, icons and line width; grouping of dense query markers.
- Reference line extras: icon, text position, line width; a computed line with Filter by / percentile.
- Dashboard export of annotations (Grafana annotations are dashboard-level queries or stored events) and of computed / labelled reference lines.
- Annotations on horizontal bars with a date axis.

## D40 — Style and Legend panels (LENS-STYLE-01)
LENS-STYLE-01 (#27). Style is one optional chart-level object, `LensState.style` (`src/lens/style.ts`), display-only and separate from the per-metric appearance (format, colour, axis side — LENS-DIM-02). Axes are stored **by role**: `left` = the value axis, `bottom` = the category axis, `right` = the right value axis; horizontal bars draw the value axis at the bottom and the panel relabels the sections accordingly, so flipping orientation never moves settings between axes. Untrusted input (URL, saved chart, draft) goes through `cleanStyle` in `decodeLens`: only known keys with known values survive, numbers must be finite, custom bounds must be ordered (an inverted pair is dropped), the custom title is capped at 120 characters and rendered as SVG text (never markup), and a legend alignment must match its position (an inside corner is not an outside side). The panel builds every change through `cleanStyle` too, and bound inputs validate against each other before applying, so the UI can't store what the decoder would drop. Defaults reproduce the old chart except Kibana's automatic axis titles and Auto legend. Rendering stays in the custom `XyChart` (click / brush interactions); value scales (`scalePos`, `valueDomain`, `valueTicks`) are pure and unit-tested; marks are clipped to the plot so custom bounds can't draw over the axes. Log scales need a positive domain: values ≤ 0 sit at the bottom and a domain starting at 0 starts at 1. Grafana mapping (`render/styleConfig.ts`, used by panel export and `panelSpec`) degrades where Grafana has no equivalent: legend top / left → bottom / right, inside → bottom, grid → list, square-root scale → linear, Data bounds → Grafana's auto range, category-axis title / ticks on time series not configurable. Brushing is off for horizontal bars (no time axis along x). Switching between XY chart types keeps the style; switching to Metric / Table / Pie drops it.

Deferred: - Legend extras from Kibana (truncate / max lines, show values in legend, legend width).
- Per-series line style (curve, points, line width) and fill opacity.
- Category-axis label truncation settings.

## D39 — Table and Metric chart specifics (LENS-CHART-01)
LENS-CHART-01 (#26). Chart-specific roles are flags on the existing dimension lists, not new lists: a bucket's `pivot: true` puts it in *Split metrics by* (Table), a metric's `role: 'max'` puts it in *Maximum value* (Metric chart). `dimensionGroups` filters by the flag, a group's `tag` sets it when adding, and `switchChart` strips the flags when leaving the chart type that gives them meaning. This keeps compile.ts untouched: the SQL groups by every bucket and aggregates every metric exactly as before, and the pivot happens on the shaped rows (`tableColumns`, `src/lens/tableChart.ts`). Summary row / colour by value map to Grafana table field-config overrides matched by column name (`custom.footer.reducers`, `custom.cellOptions`), so sorting and resizing stay Grafana's. The Metric chart is drawn by `MetricTiles` (`src/lens/render/MetricTiles.tsx`) because Grafana's Stat panel has no secondary value or per-tile progress against another metric. Not done (deferred): the trend line under a tile (needs a second, date-bucketed query), filter-for/out actions on table cells (the Inspector's Data view has them), pivot in exported dashboard panels (Grafana's grouping-to-matrix transform handles one column field and one value only), summary label text.

## D38 — Share, CSV export, new session, alert rule (DISC-SESSION-01)
DISC-SESSION-01. Share builds the link from the current address bar (Discover keeps it in sync with `encodeLogsState`) restricted to the codec's own parameter names, so one-shot parameters (trace hand-off) and anything else on the URL are never shared; "absolute" only rewrites `from` / `to` to the epoch-ms bounds the page shows. "Unsaved changes" has no session-object to compare against (saved searches are the sessions), so it means "no saved search of this view has the same search, filters (ids ignored), column choice and sort"; the comparison uses the user's raw column choice (`[]` = view defaults), as Saved searches store it. CSV export re-runs the grid query (grid projection, same columns and sort) with a 10,000-row limit instead of dumping the 200 loaded rows — Kibana exports the whole search up to a limit; cells follow the grid formatting (ISO time, JSON for maps / objects) and carry the OWASP formula guard. Create alert rule uses Grafana's own `/alerting/new/alerting?defaults=` hand-off (same as a panel's "New alert rule"), with a single-number count query (`SELECT count() AS value … WHERE <Discover conditions>`) so the threshold reads it without a reduce step; the query keeps `$__fromTime` / `$__toTime`, which the datasource fills from the rule's relative time range. New session is a full navigation to the Discover path with only `ds`, so every piece of page state starts fresh (no partial reset to keep in sync with the reducer). The menu lives in `SqlInspectorBar` beside Saved searches / Add to dashboard; LogsExplorer only passes one `session` prop.

Deferred: Save split button with `Save as` / `Reset changes` (belongs with the Saved searches menu, PLAN #30), `Open session` (the Saved searches menu already opens one), `Background searches` (no async search in this plugin; see SHARED-PERF-01), `Inspect tab` requests/responses (the diagnostics drawer covers timing and SQL). Pre-existing, not changed: Discover's "Add to dashboard" table/histogram panels don't escape `$` inside literals (Lens's export does).

## D37 — Discover session tabs (DISC-NAV-01)
DISC-NAV-01. A tab IS the Discover URL state of one exploration (the same params a shared link carries), so tabs reuse the URL codec and every existing URL behaviour instead of a second state model. `DiscoverTabsHost` (`src/pages/DiscoverTabsHost.tsx`) is the `logs` route: it owns the tab list (session storage `clickhouse-observe.discoverTabs`, per browser tab like pinned filters and the last search), reads the active tab from `_tab`, and renders `LogsExplorer` keyed by the tab id — LogsExplorer decodes its URL once at mount, so a tab switch is a navigation to the target tab's params plus a remount. LogsExplorer itself only gained two props: `tabId` (kept as `_tab` in every URL it writes) and `tabStrip` (rendered above the toolbar); every URL write is saved back into the active tab, so the last search context (#16c) and the shared search state follow the active tab without changes. Stored tabs are untrusted: on load each tab's params are decoded and re-encoded through `decodeLogsState` / `encodeLogsState` (filters through `sanitizeFilterPills`, columns later through `sanitizeColumns` in LogsExplorer, unknown views and params dropped, inbound-only trace params dropped), ids must match `^[a-z0-9]{4,24}$`, titles are stripped of control characters and capped at 80 chars (rendered as text), and list sizes are capped. Not built: tab ⋮ "Inspect" (Diagnostics is already one click away in the toolbar) and "Switch to ES|QL" (ES|QL out of scope); tabs are per browser tab (session storage), not synced across browser tabs or devices.

## D36 — Visualize Inspector (Data / Requests) (LENS-INSPECT-01)
LENS-INSPECT-01. Visualize gets its own Inspector rather than the Discover Diagnostics drawer: the spec's Data view (the chart table with filter actions and CSV) has no Diagnostics counterpart, and the Requests view only needs Visualize's chart query. The Requests view reads the tracer (`useDiagnostics`, roots of kind `lens`) instead of new state in LensPage, so the chart query effect is untouched and the server statistics come from the existing `system.query_log` enrichment. Kibana's "Clusters and shards" tab has no ClickHouse equivalent and is left out; its read rows / bytes / memory are in Statistics instead. Cell filter values follow compile.ts's `termCell` labelling: a cell equal to an enabled synthetic label is not filterable, and the `" (value)"` spelling of a clashing real value maps back to the value. ## D34 — Metric advanced options (Filter by, Time shift, Reduced time range, Normalize) and appearance (LENS-DIM-02-ADV)
LENS-DIM-02-ADV (PLAN 16g).

**Options are stored on `MetricDim`, validated on decode.** The options live on `MetricDim` (`MetricOptions` in `src/lens/metricOptions.ts`). `decodeLens` now rebuilds every metric from known keys only: before this, quick-function metrics passed through with any extra keys. `cleanMetricOptions` validates each option:
- shift and reduced range must parse as `<1–99999><unit>` within 10 years, and are stored canonical;
- the colour must be `#rrggbb`;
- enums are checked, and a custom pattern must match the numeral grammar.

**SQL is printed only from parsed values.** SQL uses only the parsed integer and a fixed unit keyword (`chInterval`), never the text. Filter by goes through `kqlToSql`, which escapes values and resolves fields. In dashboard mode a `$` in a Filter by becomes `\x24`, as for formula `kql=`.

**Time shift is one query (ARRAY JOIN), not one query per shift.**
- `compileLens` swaps the standard time condition (and its coarse partition bound) for two things: a prefilter that ORs the main window with each shifted window, and an exact check on the shifted time.
- Date buckets use the shifted time. In dashboard mode that is the explicit `toStartOfInterval(…, $__interval_s)` form, not `$__timeInterval`.
- Each metric's aggregate is conditioned on `__s = k`. Formula metrics get `__s = 0` through the new `FormulaSqlContext.rowCond`, which every aggregate in the formula ANDs with its own `kql=`.
- Ranking by count uses `countIf(__s = 0)`.
- A top-values CTE still ranks over the unshifted window.

**Filter by, shift and reduced range don't apply to formulas.** Formulas have their own `kql=` argument, and `shift=` remains deferred. The editor points users to the arguments.

**A metric's Filter by also applies when a top-values bucket ranks by that metric.**

**Appearance:**
- XY charts are custom SVG, so `XyChart` applies the format, the colour (only without a breakdown) and a right axis. Stacked charts keep one axis, since stacks are per axis in Kibana and mixing them is confusing.
- PanelRenderer charts and exported panels use one shared mapping, `withMetricAppearance`. With one metric the options go in field defaults; with several, each metric gets a `byRegexp` override on its label.

**Function changes keep the options.** `withOp` and `formulaMetric` carry them over, so a switch never loses them.

Deferred: - Time shift and reduced range inside formulas (`shift=` / `reducedTimeRange=` arguments).
- Value format on the date histogram axis and in Discover-style number fields.
- Right axis on stacked charts.
- A colour picker with Grafana's palette (a native colour input is used).

## D27 — Security: sanitize URL / saved-search columns and sort (URL-COLS)
SEC-URL-COLS. Anything restored from a URL or storage is data, not SQL. ## D26 — Surrounding documents (DISC-DOC-02)
DISC-DOC-02 (surrounding documents). ClickHouse tables have no document id, so a document is identified by its sort values, Kibana-style: (timestamp in epoch nanoseconds, row id), the row id being `cityHash64` of the timestamp and the mapped body / severity / trace id / service columns, the same fields `logRowKey` compares; rows equal on all of them are indistinguishable everywhere in the app anyway (the fixture has none). Both values are 64-bit, so queries return them with `toString` and they travel as decimal strings (a JS number would round them). The two `search_after` searches are tuple comparisons, `(ts, id) > anchor ORDER BY ts, id ASC` and `(ts, id) < anchor ORDER BY ts, id DESC`, each `LIMIT size`, plus a plain `ts >= / <= anchor` bound and the coarse partition bound so ClickHouse can prune parts. The anchor itself is a third exact-match query, so "anchor not found" (deleted, or excluded by a re-enabled filter) gets its own message. "Load N" raises the requested size and re-runs only that side. Opening from Discover first resolves the grid row to its anchor with one point lookup (same match as the detail query); rows on the context page already carry their anchor values (`__ctxNs`, `__ctxId`), so re-anchoring there needs no lookup. The URL carries the anchor in the path (`<ns>_<id>`) and the shared `filters` / `cols` / `from` / `to` plus `ret` (Discover's query string, for the breadcrumb). Filters arrive disabled; disabling never touches the pin store, so pinned filters are still pinned and enabled back in Discover. The time range is carried only for field discovery and the way back; the neighbour queries ignore it. Not done: "View single document" permalink (the context URL already identifies one document), row-level entry from the grid (the detail panel is the spec's entry point), and a hard cap on how far back the older search may scan (on a table whose sort key does not start with the timestamp an older search on a sparse filter can read many parts; `max_execution_time` still applies).

## D24 — Top values editor: rank by / direction, Other, missing, include / exclude with regex (LENS-DIM-04)
LENS-DIM-04: top values options live on `TermsDim` as optional fields (`rankBy` count|alpha|metric, `rankMetric` metric id, `rankDir`, `other`, `missing`, `include`, `exclude`, `regex`); defaults are omitted so existing URLs and default SQL are byte-identical. A bucket without Other / missing compiles exactly as before. With Other and/or missing on, a row-kind column `kN` (0 value, 1 Other, 2 missing) is returned beside it and the value column is empty for synthetic rows, so a real value spelled "Other" or "(missing)" can never merge with the synthetic bucket (the shaper keys synthetic buckets with a U+0000 prefix and shows a colliding real value as "Other (value)"; its click filter still uses the real value). "(missing)" is an extra bucket outside the top N and NULL never takes a ranking slot. Other keeps every eligible row. For Map accessors the missing test is `mapContains(map, key)` (an absent key reads as '' otherwise); for a non-Nullable column there is no "missing", an empty string stays a value. The outer ORDER BY follows the rank (alphabetical by value, custom metric by its column, count by `count()` or `m0`) in the chosen direction, with Other and (missing) always last. Every user string goes through `quoteString`, and `$` is written as `\x24` so the datasource macro expander in saved panels never sees `$__...` text. Regular expressions are validated (`regexError`): unbalanced parentheses or brackets, a trailing backslash (both could break out of the `^(?:p)$` wrapper), lookaround, back-references and invalid syntax are rejected (character classes are parsed as RE2 parses them: a `]` right after `[` or `[^` is a literal, `[:alpha:]` is one item) in the editor with a message under the field and the text is kept; the compiler also skips such patterns (URL input is untrusted) and an include list with no usable pattern matches nothing. Lists over 50 values or 200 characters per value are reported, not silently cut (URL input is still capped). Synthetic rows are not clickable (no filter), and "Custom metric" is disabled without a metric; removing the rank metric resets the stored rank to count. Labels follow the rank: "Top/Bottom N values of X" (count), "First/Last N values of X" (alphabetical), "... by <metric>" (custom). Not implemented: multi-field terms, "Aggregate by this dimension first", Rarity and Significance ranking (ascending count covers rarity), accuracy mode (ClickHouse aggregates are exact, no shard_size).

## D23 — Filter builder: range operators, per-type operators, preview (DISC-FILTER-02)

Review fixes: number boxes (Percentile, Number of values) keep a free-typed draft and apply the clamped value on blur/Enter; a new bucket never repeats a field already used; slots accept dropped fields (metric groups: number → median, other → unique count, Records → count) and are disabled when nothing fits; renaming doesn't re-run the query (`queryShape` drops names from the query key); the editor's group is looked up from the current state each render. Moving dimensions between groups by drag is still deferred.

## D16 — Lens model, compiler and rendering (LENS-AUTO-01 / LENS-SUGG-01)
LensState keeps one layer as ordered `buckets` (date histogram / top values) and `metrics`; chart roles are read positionally (XY: X, Breakdown; Table: Rows; Metric: Break down by; Pie: Slice by), so `switchChart` implements the LENS-TYPE-01 remapping by re-capping lists — dimension ids, labels and later formats survive. Suggestions follow the spec table and are unit fixtures. SQL: date histogram uses the Discover auto interval (~60 buckets), top values are restricted with `GLOBAL IN` a ranked CTE (no "Other" yet), number fields default to median (`quantile(0.5)`), non-numeric fields are cast for numeric aggregates. Results render through Grafana panels via one adapter (`src/lens/render/LensChart.tsx`); only chart types with a core panel are offered (line, area, bar, metric, table, pie). Lens state lives in the URL (`lens`); search/filters/time are the shared Discover params. The page is lazy-loaded.

**Security (security-review on PR 12):** the `lens` param is untrusted. `sanitizeLens` keeps only dimensions on discovered fields (plus the time column) and nothing runs until discovery finishes; `compileLens` also passes every field through `quoteIdentifier` (only well-formed Map accessors / dotted paths pass unquoted). Regression tests in `src/lens/__tests__/compile.test.ts` and e2e `lens-auto-01.spec.ts`. Review fixes: adding a field keeps the user's chart type; removing a line's time axis re-picks the chart; flip only for category × category; pie holds one slice dimension; duplicate metric labels get "(2)"; date buckets return as epoch ms (no timezone guessing); superseded queries are aborted.

Right-click on a bar opens a pinned popover (`BucketActionsPopover`): "Filter by time" zooms to that bucket, "Filter N selected series" adds one pill — `=` for one series, `one_of` for several (separate `=` pills would AND to nothing). ## D13 — Field list groups (DISC-SIDEBAR-01)
Groups: Selected, Popular, Available. Popular = up to 5 fields used from the list (added as a column or filtered on), counted per viewer and table in localStorage (`src/state/fieldUsage.ts`); they're listed once (not again under Available). Only fields that are rows of the list count (drilled Map keys don't), ineligible ids are dropped before the top-5 cut, and in-memory counts keep working when storage is blocked. Counts are per table (the source config has no data-view id). The type filter resets when the table changes. No Empty group: telling empty from available needs a per-field existence query, which the perf plan removed; revisit with SHARED-PERF-01. No Meta group (ClickHouse has no `_id`/`_index`). Type filter counts follow the name search.

## D12 — Grid keyboard model and Expand (DISC-TABLE-01/02)
Roving focus is per cell (`data-cell="row:col"`, `aria-selected`), not per row. Enter opens the cell's Expand popover as the spec says; Shift+Enter opens the row's detail drawer (what Enter used to do; also on the "Open detail" button). A mouse click focuses the clicked cell, but the action bar follows the keyboard cursor only while the keyboard drives the grid. PgUp/PgDn are taken only when the page really changes (one step at a time). Expand pretty-prints JSON text by re-indenting it, never re-serializing (UInt64 IDs keep every digit). Expand is a registry value action (`expand`, shown only when the host provides it), so its popover's buttons are the same Filter for / Filter out / Copy as everywhere. Display options (density, body lines; default Normal / 3) are a per-viewer convenience in localStorage, not URL state. Summary column and sample size are deferred: the OTel Body column already plays the summary role and the grid pages on demand.

## D11 — Field stats popover sampling (DISC-SIDEBAR-02)
The popover samples the 5,000 most recent matching rows (`STATS_SAMPLE_SIZE`); autocomplete keeps 500 (`DEFAULT_SAMPLE_SIZE`) to stay light; the shared cache key includes the sample size. Numeric fields get min / median / max + 10 equal-width buckets in one query (`buildNumericStatsQuery`) that reads the sample once (`groupArray` + `arrayCount`), so summary and buckets describe the same rows even with timestamp ties, and the division is guarded inside `floor` (constant fields can't hit NaN). Which fields can split the histogram is one predicate, `isBreakdownField` (scalars, not Map/JSON/Tuple/Array), shared by the toolbar picker and the popover. The fixture's `SeverityNumber` uses OTel severity numbers so numeric stats are testable. Breakdown and Visualize are registry field actions shown only when the host provides them.
