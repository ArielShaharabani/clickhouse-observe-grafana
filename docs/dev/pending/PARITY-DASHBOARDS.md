# PARITY-DASHBOARDS pending notes

**This change touches SQL generation** in two places. (1) Saved Visualize panels (`src/lens/compile.ts`, dashboard mode only): a count-only chart with a date histogram on X and Include empty rows on now ends its `ORDER BY` with `<other group columns>, b0 WITH FILL FROM toStartOfInterval($__fromTime, INTERVAL …) TO $__toTime STEP …` (`dashboardFillSql` in `src/lens/interval.ts`); the interval text is built only from a parsed `LensInterval` (number + unit table) or the datasource macros, never from user text. App-mode SQL is unchanged. (2) Discover's exported panels (`src/data/panelExport.ts`): the logs table now uses the existing grid projection (`buildLogsQuery(..., { projection: 'grid' })`, same SQL the grid runs) instead of `SELECT *`, and both Discover panels pass their SQL through `escapeDollarInLiterals` (`$` inside quoted literals / identifiers → `\x24`, the Lens convention; closes the D38 note "Discover's Add to dashboard panels don't escape `$`"). The coordinator should run the security review. Untrusted input: the panel-menu context (dashboard uid, panel id, time range, `observeVisualize` / `observeDiscover` target values from dashboard JSON), Visualize URL params `dash` / `panel` / `dfrom` / `dto`, Grafana API responses (dashboard JSON, short URL). Uids are checked against `^[A-Za-z0-9_-]{1,40}$` before any API path is built (`getDashboard` refuses others), panel ids must be positive integers below 2^31, time strings `^[A-Za-z0-9:+\-/._ ]{1,64}$`; return navigation is always `/d/<uid>?from&to` built from validated parts (the save response `url` is not used). Short URL responses are used only when they are same-origin `/goto/<uid>` URLs. Only Grafana's own relative API paths are called (`/api/dashboards/uid/<uid>`, `/api/dashboards/db`, `/api/search`, `/api/short-urls`). Hostile-value tests: `src/lens/__tests__/parityDashboards.test.ts`, `src/data/__tests__/parityDashboards.test.ts`.

**`src/plugin.json` changed** (new `addedLinks` entry `Open in Discover` on `grafana/dashboard/panel/menu`): Grafana must be restarted to pick it up.

## CHANGELOG

### Added
- **Save and return (Visualize).** Edit in Visualize from a dashboard panel now opens Visualize with `Cancel` (back to the dashboard unchanged), `Save as new` and `Save and return`. Save and return keeps the panel's title and description in the dialog, replaces that panel in place (same id, position and size) and returns to the dashboard on the time range it had. If someone saved the dashboard in between, the save is refused with a clear message instead of overwriting their change.
- **Open in Discover.** Logs panels added from Discover have `Extensions → Open in Discover` in the panel menu: Discover reopens with the panel's query, filters, columns, data view and the dashboard's time range.
- **Share in Visualize.** A `Share` button in the Visualize toolbar opens the same dialog as Discover's (absolute / relative time, Copy link).
- **Short links.** Copy link in Discover and Visualize copies a Grafana short link (`/goto/…`), with a `Short link` switch; the full link is used if shortening fails.
- **Add to dashboard: panel titles.** The Discover dialog lets you title the logs table and the volume histogram.

### Changed
- **Discover → Add to dashboard opens on Discover's time range** (it used to open on "Last 1 hour", so both panels showed No data). An existing dashboard keeps its own range.
- **The exported logs table shows Discover's columns** in Discover's order and names (Time, Level, Service, Message, …), with the message wrapping and a row count in the footer, instead of every raw column.
- **Duplicate dashboard titles** are flagged in the Add to dashboard dialog while typing, and Grafana's name conflict (and other save errors) are explained in the dialogs instead of a raw error.
- **Legends of saved charts** show the breakdown value (`payments`) instead of `m0 payments`, and the volume panel shows `error` instead of `count error`.
- **Saved time-series count charts no longer draw lines across empty buckets**: empty buckets are 0, as in Visualize with Include empty rows.
- **The `Saved` button is now `Saved searches`** (secondary, folder icon, caret) and has no tooltip covering the menu's `Save current`.

### Fixed
- Add to dashboard checkbox labels were centred away from their boxes.
- `$` in a search value inside Discover's exported panels could be interpolated by Grafana as a dashboard variable.

## Decision

PARITY-DASHBOARDS (Kibana 9.5.6 comparison, user request 2026-11-19). **Save and return:** the panel-menu link adds the dashboard uid, panel id and the dashboard's time (`dash`, `panel`, `dfrom`, `dto`) to the Visualize URL, validated in `readDashboardReturn` / `editInVisualizePath`; nothing else about the session changes (they are not part of the remembered search context or the share link). Visualize loads the dashboard once on entry (`loadReturnTarget`): its panel title / description prefill the dialog and its `version` is the optimistic lock — the save replaces the panel by id in the JSON loaded at entry (`replacePanelInDashboard`, rows included) and posts it with `overwrite: false`, so Grafana answers `412 version-mismatch` if the dashboard changed since; we explain it rather than merging. The dialog is kept (Kibana saves directly) so the title can still be changed; `Save as new` is the old flow. A library-panel reference replaced this way becomes an inline panel (updating the library element would change every dashboard using it). **Discover → dashboard:** a new dashboard gets Discover's range (relative strings kept); existing dashboards keep theirs. The logs panel stays a Grafana `table`: the `logs` panel shows one text line per document and hides the other fields behind a details toggle, so Discover's chosen columns can't be shown side by side; the table gets Discover's columns through one `organize` step over the grid projection, fixed widths for Time / Level / Service / Trace, wrapped Message and a footer row count (of the rows shown — the panel keeps Discover's 200-row limit, so it is not the total hit count). "Open in Discover" uses the same panel-menu extension pattern as Edit in Visualize (`observeDiscover` on the target, the Discover URL parameters minus time, filtered and capped; Discover sanitizes them as a shared link). **Legends:** Grafana's `partitionByValues` labels each series field with the split value and names it `<field> <value>`; a rename before partitioning didn't survive in the comparison Grafana, so split time series keep the metric aliases and set `displayName` by override (`byName m<i>` → `${__field.labels.b1}`, or `… · <metric>` with several metrics); per-metric appearance overrides match the alias in that case. The volume panel does the same with `${__field.labels.level}`. **Empty buckets:** Grafana fills nothing for a table-format query and `insertNulls` needs a fixed interval, so count-only charts gap-fill in SQL with `WITH FILL`, the breakdown columns leading so ClickHouse fills per breakdown value (`use_with_fill_by_sorting_prefix`, default on since 23.x); other metrics keep gaps. **Short links:** Grafana's `/api/short-urls` with the path relative to the root; the dialog shows the full link until the short one arrives and falls back to it on any error. **Saved searches button:** secondary + folder icon + caret, no tooltip.

Deferred: - Kibana's direct (no-dialog) Save and return, and updating a library panel's element on Save and return.
- A total hit count on the exported logs panel (needs a second query / a stat panel); the footer counts the rows shown.
- Legend names for category charts with a breakdown and several metrics (`joinByField` path) — unchanged.
- Gap filling for non-count metrics in saved panels (Grafana `insertNulls` only with a fixed interval).
- Storing the time range when adding to an existing dashboard (Kibana's "Store time with dashboard" option).
- Short-link expiry / cleanup (Grafana's own policy applies).
