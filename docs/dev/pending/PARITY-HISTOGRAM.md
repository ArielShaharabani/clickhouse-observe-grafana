# Kibana parity: Discover histogram and time (PARITY-HISTOGRAM)

**SQL:** unchanged. Every query already used inclusive bounds (`ts >= $__fromTime AND ts <= $__toTime` in `buildWhereConditions`, and the same in Lens `compile.ts`). The 2,160 vs 2,161 difference was client-side: `fillEmptyBuckets` dropped the bucket starting exactly at the range end, and the `N rows (count)` caption sums the buckets. The only query-shape change is the histogram interval: a too-fine fixed interval now runs as `toStartOfInterval(ts, INTERVAL <n> SECOND)` with a round `n` (the auto path's existing shape) instead of being disabled. New untrusted URL input: `refresh` (validated by `cleanRefreshInterval`: `^[1-9]\d{0,3}[smhd]$` and ≥ 5 s, else ignored; it never reaches SQL) and `bd=field:<name>` resolution (`resolveBreakdownField` only looks the id up among discovered fields; the SQL still comes from the discovered `FieldModel`, never from the URL). Brush times are numbers computed from pointer positions.

## CHANGELOG

### Changed
- **Discover auto-refresh is off by default** (Kibana: paused). It used to start at 30 s, re-running the search every 30 seconds even on an absolute past window. A chosen interval is kept in the URL (`refresh=1m`) and restored from links.
- **Histogram starts with "No breakdown"** (Kibana's default; it used to break down by severity). `bd=severity` or a field breakdown in the URL still applies.
- **Finer auto histogram intervals:** 7 days now buckets at 3 hours (56 bars, as Kibana) instead of 6 hours; 15-minute and 12-hour steps added. Visualize's automatic date histogram uses the same steps, so it changes the same way.
- **Too-fine intervals are scaled, not disabled:** Second / Minute / Hour / Day are always selectable. When an interval would make more than 1,000 bars it is scaled to the finest round interval that fits, and the caption shows `(interval: Minute, scaled to 15 minutes)` with a `⚠ Scaled to 15 minutes` notice (Kibana: "scaled to 10 minutes").
- **Histogram axis:** ticks on round times (every 30 minutes, every hour, midnight …) spaced so labels never collide; 7-day ranges read `1st … 7th` with `January 2026` (Kibana), sub-day ranges `HH:mm` with the date under the first tick and each new day, multi-month ranges `Jan 2026`.
- **Partial buckets** (only partly inside the time range) are drawn faded on a grey band, with a tooltip note.

### Fixed
- **Histogram brush snapped inward to whole buckets** (a 4.8 h → 14.4 h drag became 06:00 → 12:00) and a drag inside one bucket gave `from == to` and an empty result. The brush now uses the exact dragged times (whole seconds, at least one second or one pixel wide) and the new range is re-bucketed. A click zooms to the clicked bucket (start → end) instead of a half-bucket window around its start.
- **Row count one short of every other count** (2,160 vs Kibana's and the field popover's 2,161 for 08:00–12:00): the histogram dropped the bucket starting exactly at the range end, which holds rows at `to` (the range includes its end).
- **The histogram's two-line first axis label overlapped the `N rows (count)` caption** (document panel open, or 0 rows): the axis row grows to two lines when needed.
- **A malformed `bd` URL parameter was ignored silently while the URL kept it:** `bd=field:ServiceName` (no `col:` prefix) now resolves to the column and the URL is rewritten to `field:col:ServiceName`; an unknown field or junk value is dropped from the URL.

## Decision

Kibana parity for the Discover histogram and time (comparison against Kibana 9.5.6 on the same fixture, 2026-11-19). (1) **Brush:** `brushRange` (`src/components/_histogramInterval.ts`) maps the dragged pixels to time inside each bar slot (bar `i` plus a fraction of its width; linear for fixed-width buckets), clamps to the drawn extent, rounds outwards to whole seconds and enforces a minimum width of max(1 s, one pixel of time). Whole seconds because the ClickHouse datasource's `$__fromTime` / `$__toTime` are second precision (`toDateTime(intDiv(ms, 1000))`): a millisecond `to` would silently drop up to 999 ms of rows while the caption claimed them. Switching every query to the `_ms` macros was not done here (wide SQL churn: Discover, Lens, alerts, panel exports). The Visualize XY brush (`src/lens/render/XyChart.tsx`) has its own linear pixel→time mapping (no snapping) and shares no code with this one; it still emits millisecond times. (2) **Inclusive end:** SQL was already `<= to`; `fillEmptyBuckets` now keeps any bucket the query returned, including one starting at `to`, and still adds no empty filler there. Counts that change: a range whose end instant holds a row gains it (e.g. a one-day window on the fixture, midnight to midnight, is 5,761 rows, not 5,760; whole-fixture counts are unchanged because the last fixture row is 23:59:45). (3) **Intervals:** auto steps gained 15 min, 3 h, 12 h; `resolveInterval` scales a fixed second/minute/hour/day interval above `MAX_BUCKETS` (1,000) to the smallest auto step that is a multiple of the unit and fits, returned as `SECOND × n` with `scaledTo`; week/month/year are calendar widths and never scaled. The Visualize hand-off still carries the chosen unit (Lens applies its own interval rules). (4) **Ticks:** `timeTicks` (`src/components/_histogramTicks.ts`) picks the finest round step whose labels fit (≥ 80 px apart and label width + 16 px), aligned in the browser's zone (days step by calendar days so DST can't move midnight ticks); second lines at most one per ~100 px. Calendar-unit buckets keep index-based date labels. (5) **Partial buckets:** `isPartialBucket(start, width, range)` = starts before `from` or ends after `to` (a bucket ending exactly at `to` is whole). (6) **Defaults:** breakdown default is `none` (derived; `bd` wins); auto-refresh default paused, URL `refresh` validated, encoded only when on. (7) **`bd` normalisation:** `resolveBreakdownField` accepts the exact id or `col:<id>`; once discovery has settled for the URL's own view (`fieldsFor === discoveryKey(config)`, not loading, fields present) an unresolved id is cleared, which drops it from the URL; junk never decoded in the first place.

## Deferred
- Millisecond-precise time bounds (`$__fromTime_ms` / `$__toTime_ms` everywhere). Brush and click ranges are whole seconds, so nothing is lost today; sub-second ranges typed in the picker are still truncated to the second by the datasource macros.
- Kibana's red "now" line on the histogram.
- Visualize XY brush: not touched (owned by the XY-chart work); it maps pixels to milliseconds without snapping, so it doesn't have the snapping bug, but its times are not rounded to whole seconds.
- A scaled interval is not carried into Visualize as the scaled width (Explore in Visualize passes the chosen unit; Lens decides its own buckets).
- The field popover's "sample records" wording when every row was used (finding in the same comparison; belongs to the field-popover work).
