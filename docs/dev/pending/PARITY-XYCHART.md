# PARITY-XYCHART pending notes

**No SQL change.** Everything here is rendering, state shaping and display-only state. `compileLens` is untouched; `shapeLensRows` only reorders the series it returns (`orderSeries`); `queryShape` already strips `style`, so the new `style.colors` never changes the chart query (jest asserts it). Untrusted input: the `lens` URL param / draft / saved panel state now may carry `style.colors` — `cleanStyle` → `cleanSeriesColors` keeps only string keys up to 200 characters mapped to `#rrggbb` (lower-cased), at most 50 entries; lookups use own properties only (`seriesColorOf`), and a `__proto__` key stays a plain key. Series names and colours render as text / SVG attributes, never markup. No security review needed beyond the usual.

Shared code touched: `src/components/a11y/dialog.tsx` `moveMenuFocus` now also walks `role="menuitemradio"` items (the legend colour swatches); menus without such items behave as before. No change to Discover's histogram or to shared time / tick helpers: the new time ticks live in `src/lens/render/timeTicks.ts`, used only by the Visualize XY chart. `src/lens/panelExport.ts` changes one line (Line never stacks).

## CHANGELOG

### Added
- **Visualize XY tooltip (Kibana parity).** Hovering a Bar / Line / Area chart shows a crosshair and a tooltip with every series at that X (time header `Jan 5, 2026 @ 09:00`, colour, name, value with thousands separators), the series under the pointer highlighted; focusing a bar or point with the keyboard shows it too.
- **Legend colour picker.** The legend ⋮ menu has a colour palette and `Reset color`; the choice is kept in the chart state (URL, draft, saved chart) and does not re-run the query.

### Changed
- **Stable series colours.** A breakdown value keeps its colour across chart types and click-filters (colour by value, not by position).
- **Legend and stack order** follow the Top values rank (count descending by default), with Other / (missing) last.
- **Value axis** ends on a nice tick (a 140 peak → 0–140 by 20 instead of 0–200) and count axes never show fractional ticks.
- **Time axis** ticks fall on round times with the date under the first tick; no automatic "Timestamp" axis title; partial first / last buckets are shaded.
- **Lines** are drawn without a dot on every point (dots on hover, focus or isolated points).
- **Numbers** in the XY chart use thousands separators (`9,264` instead of `9.3K`); axes abbreviate only from a million.
- **Line has no sub-type** (Kibana Line never stacks): the Stacked / Percentage / Unstacked control is hidden for Line, which always draws unstacked; old links with line + stacked still load.
- **Chart type switch** keeps the previous chart on screen until the new one is ready (no blank frame).

### Fixed
- Brushing a time range now also works when the drag starts on a bar; a click without movement still opens the filter chooser.
- Line charts with a Percentage sub-type kept from Bar / Area no longer draw percentages (chart, `panelSpec` and dashboard export).

## Decision

PARITY-XYCHART (Kibana 9.5 side-by-side comparison of the Visualize XY chart). (1) **Line has no stacking**: rather than make Stacked work for lines, Line follows Kibana — no sub-type control, always unstacked in the chart, `panelSpec` and panel export. The stored `subType` is kept (not cleared) so Line → Bar / Area restores it and old `line` + `stacked` URLs load unchanged; `chartTitle` never adds a sub-type to Line. (2) **Colours by value**: each breakdown series' colour key (`seriesColorKey`: its name, synthetic Other / (missing) prefixed so a real value spelled "Other" differs) hashes with FNV-1a to one of the palette's first 10 colours (`assignColorSlots`); series are placed in legend order, so on a collision the larger series keeps its colour and the next takes the next free one, beyond 10 the rest of the palette. A value alone (after a click-filter) always gets its own hash slot. Series without a breakdown keep their position colours (metric order is the user's). Precedence: legend choice (`style.colors[name]`) > metric colour (non-breakdown series) > automatic. The dashboard export still uses Grafana's palette by position (no per-value override yet). (3) **Order**: `orderSeries` in `shapeLensRows` sorts a Top values breakdown by its rank (count total of the first metric, the rank metric's total for Custom metric, alphabetical for Alphabetical, in the rank direction), synthetic series last, several metrics of one value kept together; other breakdown kinds keep the query's order. It changes `LensResult.series` order for everything that reads it (XY, the click / legend handlers index into the same array, so they stay consistent). (4) **Ticks**: d3-style `tickStep` (span / count rounded to 1 / 2 / 5 / 10 × 10ⁿ, `integer` floors the step at 1 when every plotted value is whole) with about five ticks (fewer on a short plot); `valueDomain` rounds outward to that step in two passes. Custom bounds keep their exact ends. (5) **Time ticks**: local-time round steps chosen so ticks are ≥ 80 px apart; positions on bucket starts (the band's left edge) like Kibana; the date row under the first tick and at each date change. The automatic bottom-axis title is empty for a date histogram X (`autoAxisTitles`), so Style → Auto stays "the automatic title" and Custom still works; exported time-series panels had no category-axis title anyway (D40). Partial buckets: the first bucket starting before `from`, the last ending after `to` (bucket width from the query's interval). (6) **Brush**: the mousedown handler moved from the background rect to the `<svg>`, so a press on a bar starts it too; it only becomes a brush after 4 px of movement, and the click that ends a brush is swallowed (flag cleared on the next tick). (7) **Tooltip**: state `{xi, si, px, py}` from pointer position (band index; the bar segment containing the pointer, or the nearest line point within 24 px), rendered as an absolutely positioned `role="tooltip"` div with `pointer-events: none`, flipped to the left in the right half; focus / blur of a mark drive the same state. The native `<title>` on marks was removed (annotations / reference lines keep theirs). (8) **Numbers**: `formatNumber` (`en-US` grouping, up to 3 decimals, Kibana's `0,0.[000]`) for values and accessible names; `formatAxisNumber` abbreviates only ≥ 1M. A metric's own value format still wins. (9) **Type switch flash**: `LensPage` keeps the last result with the state it was shaped for and a `baseKey` (the query key without chart type / sub-type); while a new query runs and the base key matches, it draws the old chart (`data-testid="lens-chart-stale"`, `aria-busy`, not interactive) instead of the spinner. Any other change (fields, filters, time) still shows the spinner, so tests that wait for new data are unaffected.

## Deferred

- **Dashboard export colours**: exported Grafana panels still colour series by position (Grafana's classic palette); per-value overrides (`fieldConfig.overrides` by name) for the stable colours and the legend choices would make dashboards match. Easy follow-up in `src/lens/panelExport.ts` using `assignColorSlots`.
- **Pie / Metric / Table** don't use the stable colours yet (Pie goes through Grafana's piechart by position): reuse `assignColorSlots` + `seriesColorKey` from `src/lens/render/seriesColors.ts`.
- Tooltip on touch devices (no hover); the tooltip lists at most 20 series ("+N more").
- Kibana's multi-layer time axis shows the date row under every day boundary of the visible range; ours does the same only at tick positions (the first tick of a new day).
- Partial-bucket shading uses the query's bucket width; calendar months / years use the approximate width (`bucketMs`).
