# R3-FUNCTIONS (LENS-CALC-01) pending notes

**This change touches SQL generation** (`src/lens/compile.ts`, `src/lens/formula.ts`, new `src/lens/calc.ts`, `src/lens/interval.ts`); the coordinator should run the security review. With any time-series calculation or `overall_*` in the chart, `compileLens` wraps its grouped query: the inner query is the existing one (CTEs, ARRAY JOIN time shift, top values `GLOBAL IN`, Filters `arrayJoin`) with every aggregate as `a<k>` (non-additive ones `…OrNull`), grouped by the series' date bucket as a DateTime (`__d`, app mode) and gap-filled with `ORDER BY <other group cols>, __d WITH FILL …`; the outer SELECT applies window functions (`sum … OVER (PARTITION BY <breakdown cols> ORDER BY __d ROWS …)`, `lagInFrame`, `groupArray` + `arrayReduce('avgOrNull', arraySlice(…, -<window>))`, `sum/avg/min/max(a) OVER (PARTITION BY …)`), converts `__d` to epoch ms and orders / limits. Saved panels (`dashboard` mode) use the same shape over `$__timeInterval` buckets and the existing dashboard WITH FILL. One query, no extra round trip. New plain aggregates: `stddevPop[If]OrNull`, `argMaxIfOrNull(x, <time expr>, x IS NOT NULL …)`. Untrusted input: the `lens` URL / saved charts. The moving-average window is clamped to an integer 1–100 (`clampWindow`) and printed by us; a calculation's inner metric (`ref`) is rebuilt by `cleanRef` (known op from a fixed list — Cumulative sum only count / sum —, string field, clamped percentile; nothing else rides along) and its field must be a discovered field (`sanitizeLens`), then quoted with `quoteIdentifier`. Formula `window=` is a lexer number token validated as an integer 1–100 and re-clamped when printed; formula field references go through the existing field map. Aliases (`a<k>`, `__d`, `__c`, `b<i>`, `k<i>`, `m<i>`) are ours. No user text is concatenated into SQL. Side fix: saved panels with a week / month / year interval now bucket as `toDateTime(toStartOfInterval(…))` (and fill from `toDateTime(toStartOfInterval($__fromTime, …))`) — `toStartOfInterval` returns a Date for those units and WITH FILL rejected the Date/DateTime mix (`INVALID_WITH_FILL_EXPRESSION`), so such panels with Include empty rows failed. Normalize by unit on a saved panel with a typed fixed interval now divides by `greatest(<min>, $__interval_s)` (the bucket length) instead of `$__interval_s`.

## CHANGELOG

### Added
- **Standard deviation and Last value (LENS-CALC-01).** New quick functions: population standard deviation of a number field (as Elasticsearch's `std_deviation`), and the value of the newest document (by the data view's time field) that has the field.
- **Time-series calculations.** A "Calculations" group in the metric editor: Cumulative sum, Differences, Moving average (Window size 1–100, default 5) and Counter rate (per second). Each wraps a metric ("Moving average of Median of duration"; Cumulative sum adds counts or sums) and is calculated per series. They need a date histogram: without one they are disabled with the reason, and a chart that loses its date histogram shows why instead of wrong numbers.
- **Formula functions:** `standard_deviation`, `last_value`, `cumulative_sum`, `differences`, `moving_average(…, window=5)`, `counter_rate`, `overall_sum`, `overall_average`, `overall_min`, `overall_max` — e.g. `count() / overall_sum(count())` for percent of total. The function reference is grouped (Aggregations, Time series, Overall, Math).
- Every quick function has a short explanation (tooltip and a note under the grid).

### Changed
- Empty metric values (a bucket with no values, the first bucket of a difference) are gaps in charts and empty table cells instead of 0; counts stay 0.
- Top values "Rank by → Custom metric" lists only metrics that can rank (not calculations, except Cumulative sum, which ranks by its total).

### Fixed
- Saved dashboard panels with a week / month / year interval and Include empty rows failed with a ClickHouse WITH FILL type error.
- Normalize by unit on a saved panel with a typed minimum interval used the dashboard interval instead of the bucket length.

## Decision

LENS-CALC-01 (Kibana comparison round 2, #15). Semantics mirror Kibana 9.5's datatable functions, read from its bundles (`cumulativeSumFn`, `derivativeFn`, `movingAverageFn`, `counterRateFn`, `overallMetricFn`): cumulative sum carries the running total over empty values; differences is empty when the current or previous value is empty (a gap breaks the chain); moving average is the mean of the last *window* non-empty values before the current one (current excluded, empty values skipped, empty when the current value is empty); counter rate is the difference, or the new value when it dropped (reset), divided by the bucket length (Kibana's mandatory time scale, default per second; partial edge buckets are not scaled down); overall_* ignore empty values and are per series, where the series is defined by the date histogram / intervals and split by top values / filters, over all rows when neither exists (Kibana's docs). Cumulative sum's inner metric is Count or Sum only (Kibana's restriction). Time-series functions require a date histogram (Kibana: "To use this function, you need to configure a date histogram dimension as well"); overall_* do not. Formula `counter_rate` is per bucket ("uses the current interval when used in Formula"); converting a quick Counter rate to a formula keeps per second through Normalize by unit. Computation is SQL window functions over the grouped query rather than client-side, so Visualize, the Inspector's rows and saved dashboard panels show the same numbers; gap filling moves into SQL (WITH FILL) for these charts because the calculations must see empty buckets (count / sum / unique = 0, other aggregates empty via `-OrNull`). Drop partial intervals filters before the window in app mode (saved panels ignore it, as before). Ranking top values by a calculation is not offered (no single value per series), except Cumulative sum, whose total is its inner metric's total. Window functions cannot be nested or used inside an aggregation. Last value skips documents without the field (Kibana's `exists` filter) and is numeric only.
